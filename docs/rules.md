# Rules

Rules are deterministic pattern or repository analyses. Severity indicates practical risk; confidence indicates the strength of static evidence. Pattern examples are illustrative and never execute code. A rule can be disabled or overridden through configuration.

| ID       | Name                                            | Category      | Default severity | Confidence | Detects / recommendation / limitation                                                                                     |
| -------- | ----------------------------------------------- | ------------- | ---------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------- |
| SEC001   | Potential hardcoded credential                  | Security      | High             | High       | Credential-like assignment; move it to managed configuration. Pattern matching can match non-production fixtures.         |
| SEC002   | Private key detected                            | Security      | Critical         | High       | PEM private-key header; revoke/rotate and remove it from source control. Does not validate key material.                  |
| SEC004   | Sensitive environment file tracked              | Security      | High             | High       | Non-example `.env` in a Git project; remove/rotate it. Presence does not prove Git tracking in every layout.              |
| SEC006   | Dangerous dynamic code execution                | Security      | High             | High       | `eval`/`Function`; replace with explicit dispatch. Context is not interpreted.                                            |
| SEC007   | Unsafe shell command construction               | Security      | High             | Medium     | Interpolated shell primitive; use argument arrays and validation. Shell pattern is heuristic.                             |
| REL001   | HTTP request without explicit timeout           | Reliability   | Medium           | Medium     | Common outbound HTTP call without visible timeout; add bounded timeout. Wrapper behavior is not inferred.                 |
| REL002   | Empty catch block                               | Reliability   | Medium           | High       | Empty JavaScript/PHP catch body; handle or document errors. Deliberate ignores need review.                               |
| REL005   | Missing graceful shutdown handling              | Reliability   | Low              | Low        | Node project with no visible signal handler; close resources on termination. Framework abstractions may hide handling.    |
| CFG001   | Debug mode enabled                              | Configuration | Medium           | High       | Explicit debug setting; disable in production. Environment context is not known.                                          |
| CFG003   | Hardcoded environment-specific URL              | Configuration | Low              | Medium     | Local/private URL in source; use validated configuration. Development code can be intentional.                            |
| CFG006   | Default credential detected                     | Configuration | High             | High       | Common default password assignment; replace with a unique secret. Test data can match.                                    |
| OBS001   | No obvious structured logging                   | Observability | Low              | Low        | No common logger usage; adopt structured fields where useful. Custom logging is not recognized.                           |
| OBS002   | Console logging in production-oriented code     | Observability | Low              | Medium     | Console log/debug/info; use intentional structured logging. Console can be valid in some deployments.                     |
| OBS003   | Missing obvious health-check endpoint           | Observability | Low              | Low        | No visible health-like route; add readiness behavior where appropriate. Infrastructure health checks may exist elsewhere. |
| TST001   | No obvious test suite detected                  | Testing       | Medium           | Medium     | No test file convention found; add automated tests. External test layout may be missed.                                   |
| TST003   | Large module without corresponding test         | Testing       | Medium           | Medium     | 300+ line module without same-name test signal; prioritize behavior tests. Name matching is heuristic.                    |
| ARC001   | Very large source file                          | Architecture  | Medium           | High       | 500+ lines; review responsibility boundaries. Size alone is not a defect.                                                 |
| ARC003   | Circular dependency                             | Architecture  | High             | High       | Two-way direct local import; extract/invert dependency. Dynamic imports are not modeled.                                  |
| ARC004   | High fan-in module                              | Architecture  | Medium           | Medium     | Eight+ direct local dependents; review interface and tests. Import resolution is intentionally limited.                   |
| ARC005   | High fan-out module                             | Architecture  | Medium           | Medium     | Eight+ direct local imports; review orchestration. External imports are excluded.                                         |
| ARC007   | Architecture hotspot                            | Architecture  | Medium           | Medium     | Ten+ changes in 90 days; review change drivers. Git history does not prove debt.                                          |
| ARC008   | Highly changed module with many dependents      | Architecture  | High             | Medium     | Five+ recent changes and dependents; review boundaries. Depends on resolvable local imports.                              |
| REACT001 | List rendering without stable key               | Framework     | Medium           | Medium     | JSX map return without visible key; use stable data key. Multiline/indirect JSX can evade detection.                      |
| REACT004 | Direct DOM manipulation                         | Framework     | Low              | Medium     | Common `document` APIs; prefer refs/declarative UI. Imperative DOM access can be legitimate.                              |
| NEXT002  | Potential sensitive public environment variable | Framework     | High             | High       | Sensitive-looking `NEXT_PUBLIC_` name; make it server-only. Name does not prove a secret value.                           |
| NODE002  | Dangerous child_process usage                   | Framework     | High             | Medium     | String command to exec primitive; prefer argument arrays. Input flow is not traced.                                       |
| PHP001   | Dangerous PHP dynamic execution                 | Framework     | High             | High       | PHP eval/assert/create_function; remove or tightly constrain. Static patterns only.                                       |
| LAR001   | Laravel APP_DEBUG enabled                       | Framework     | High             | High       | `APP_DEBUG=true` in an environment file; disable for production. Does not know deployment environment.                    |
| LAR004   | Laravel mass-assignment exposure                | Framework     | Medium           | Medium     | Empty `$guarded`; define fillable/constraints. Validation may exist elsewhere.                                            |
